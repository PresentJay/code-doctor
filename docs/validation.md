# Validation and limits

This document records the scope of evidence, not a claim that people understand code better merely because tests pass.

| Area | Verified behavior | Not established |
|---|---|---|
| Git capture | Exact unit coverage, source fingerprints, pinned comparison commits; staged/worktree cancellation, rename/deletion/binary/empty changes; rejected unsupported states | Automatic correctness or scope judgment |
| CLI and MCP | Shared service and real stdio client; complete guides and archived originals; stale feedback rejection; several opinions corrected and resolved against one new review | Every model choosing or following the skill automatically |
| Automatic installation | Both generated host commands receive ordinary prompt events and respect opt-outs; Codex user-level MCP setup preserves unrelated settings and rejects edited managed entries | Claude user-level MCP setup; every wrapper loading settings; automatic trust; Windows installation |
| User-level source skill | Linked CLI launcher runs in two isolated projects; exact first inventory contains only the original application change, without project settings or skills | A running host loading that link; Windows setup; wrapper discovery |
| Setup | Preserve unrelated JSON/TOML, comments, large integers and permissions; refuse edited managed files and unsafe paths; add only this tool | Every client's trust/approval UI |
| Optional viewer | Local navigation, exact batch feedback, stale-state handling, and return to an active MCP waiter | Waking a stopped agent; every host keeping the waiter open |
| Languages | English fallback plus Korean/Japanese/Simplified Chinese catalogs, matching placeholders, in-place language changes and unchanged original content | Independent native-speaker review; Traditional Chinese |
| Codex | Controlled CLI model fixture received two viewer opinions, corrected and tested code, then prepared and waited for a revised review | Automatic setup in every project; desktop or wrapper round trips across all workspaces |
| Claude | Prior MCP initialization/connection and plugin validation | Actual model execution without an available account |
| Conductor | A Codex session opened the local viewer, received two submitted opinions, applied and tested them, and prepared a revised review; a separate workspace displayed native diff and line guidance | Native feedback delivery and a second feedback completion in those sessions |

Run `npm run check` for the current source. It covers disposable Git repositories, actual CLI/stdio MCP, source/version validation, setup preservation, the shipped viewer handlers, locale completeness and package assets. Private branches currently use the existing isolated runner; public events must use GitHub-hosted CI. Exact final commit and CI results belong to each PR.

The global-preview viewer check used a disposable two-block repository in the Codex in-app browser, at the default desktop size and 390 × 844. All four languages kept the selected block, source, review ID and multilingual draft intact. Two saved opinions survived language changes, copied together with their original text, and remained after reopening the authenticated link. A Japanese unauthorized state displayed localized recovery guidance. This checks the optional viewer, not Conductor or Claude model execution.

A later controlled test used a logged-in Codex CLI with a temporary MCP configuration, normal workspace-write sandbox and a disposable repository. The model was explicitly asked to open the prepared review and wait. Two synthetic opinions entered in separate viewer blocks arrived together; the same turn applied them, passed the boundary tests, prepared a revised review and waited again. The existing viewer opened that review, and an empty completion ended the turn. A separate CLI test without an explicit MCP repository argument found the CLI working repository. These results do not establish automatic user-level MCP installation, desktop or Conductor behavior, or Claude model execution. No credentials were copied and hook trust was not bypassed.

For the user-level MCP change, a controlled Codex CLI session started outside Git with the documented `--skip-git-repo-check` option and a temporary connection matching the generated entry. After reading the new skill, it selected the task repository and read its saved review. Isolated installer tests verify the generated Codex configuration and repeated installation. This does not establish that a desktop or wrapper reloads user-level settings, or that Claude's user-level MCP is configured.

The updated installation was also applied locally with the previous runtime preserved as a backup. In a new Codex CLI session, an ordinary request for a bug fix and visual code review, without naming Code Doctor, led the agent to select the repository, modify and test the code, and open a waiting review. Two synthetic viewer opinions were applied and tested in the same turn; the revised review opened in the same viewer and an empty follow-up completed it. The agent initially replaced the original task context during recapture, causing two resolution failures; it recovered by restoring the original context. The skill and tool guidance now explicitly instruct agents to preserve that context. This guidance change has not itself been tested in a new model run.

A controlled Conductor Codex workspace used the locally installed MCP and an explicitly requested visual review. The first review opened in the system browser; two synthetic opinions submitted together reached the waiting agent, which edited and tested the example, resolved both opinions and prepared a revised review. The revised review appeared in the existing viewer. A second feedback completion was not observed. Conductor's native diff could not load in this particular workspace because its selected target branch had been deleted after merging; this does not establish that native diffs fail in a workspace with a valid target. The initial link omitted a language, so the browser displayed English controls despite the Korean conversation.

The revised MCP accepts a supported `lang` when opening a review; a real MCP link with `ko` opened the Korean interface in a browser. The updated skill instructs the agent to supply the person's language when known. The instruction has not yet been observed in another Conductor model session.

In a fresh Conductor workspace whose comparison target and checkout were the merged `main`, a Codex session used the installed Code Doctor without being named in the request. It prepared two reading comments; the native diff displayed syntax-highlighted source with one Korean explanation beside the relevant line. The person could not find how to enter feedback from the original instruction. Conductor's [changelog](https://www.conductor.build/changelog/page/2) describes clicking a diff line number to open a comment, and its [workflow guide](https://www.conductor.build/docs/concepts/workflow) says inline comments become attachments to send to the agent. The revised skill makes that entry point explicit; the instruction and native feedback delivery have not yet been verified in this workspace.

The guide distinguishes a complete inventory from the code included in excerpts. Before/after paths and index/worktree stages stay separate, including when the same line changes twice. Binary and metadata-only units never disappear into a zero-line count. This is presentation evidence, not completed review or approval.

The public preparation removes unrelated service integration and owner-specific operational narratives from the maintained tree. It does not rewrite Git history, redact past GitHub discussions, change repository visibility or publish a registry package. An exported source snapshot excludes Git history and private local artifacts. These limits must be considered before making the existing repository public.

The automatic-guidance check used a clean temporary user installation and an ordinary Codex CLI request to fix an empty-cart total. With the hook enabled, Codex fixed and tested the code, then captured, planned and read the complete guide without the request naming Code Doctor. With a repository opt-out, the same request fixed the code without creating review storage. The inspected test hook ran under Codex's one-invocation trust option; no persistent host trust or personal settings were changed. This establishes the controlled CLI behavior, not every wrapper's hook discovery or the human trust UI. Both host-generated hook commands and an installed package were also exercised directly.

A parent-directory regression check starts Codex outside Git and asks it to fix `./project` without mentioning Code Doctor. The agent resolves that child repository, checks its status with the real session ID, fixes and tests the code, prepares one complete guide, and includes the actual changed code in its final response. With guidance disabled for the child repository, the same fix succeeds without creating review storage. These controlled CLI observations do not establish desktop/Conductor discovery, Claude model behavior, or universal compliance with the same-turn completion instruction. No Stop hook or additional model continuation enforces delivery.

The opt-out regression exercises three isolated Codex requests: from a disabled parent, fixing an enabled child repository produces a complete guide with code while the parent remains disabled; fixing the disabled target itself produces no review storage and does not re-enable it; an explicit conversation re-enable request uses the actual host session ID and leaves source unchanged. Repository/session opt-outs now retain control context, while global disable stays silent. Both installed host command formats are exercised directly. These checks do not establish Claude model execution, desktop/Conductor automatic loading, or human approval of a new hook command.
